# дора хочет

страница `/wishlist` в стиле основного сайта

## интерфейс

- 39 желаний, поиск, категории, «очень хочу» и локальная подборка
- png с прозрачным фоном размещены вместе с сайтом в `wishlist/items`
- текст без точек, поездка называется «новый год в тёплом месте»
- портрет пользователя не изменяется

## бронь подарков

- `reservations.js` работает с изолированным supabase edge function `wishlist-reserve`
- тг используется как заявленный идентификатор, это не авторизация и не доказательство владения аккаунтом
- сам тг не сохраняется в таблице и не показывается доре или посетителям
- сервер сохраняет hmac-метку тг для ограничения повторных броней и sha-256 случайного ключа отмены
- общедоступный ответ содержит только включённость бронирования и список занятых подарков
- случайный ключ управления создаётся в браузере дарителя и сохраняется в нём
- личная ссылка содержит ключ только в url fragment, который не передаётся серверу при открытии страницы
- отмена и продление доступны только с ключом управления, не по одному тг
- срок 90 дней, до 5 активных броней на техническую метку тг, ограничение попыток по сети
- подарок занят атомарно: из двух одновременных запросов выигрывает один
- rls включён у всех таблиц wishlist, доступ к rpc только у service_role через edge function
- настройки и данные crm не используются и не меняются

## границы приватности

в обычном интерфейсе владелица видит только «забронировано» без контакта дарителя
это не анонимность от администратора инфраструктуры, который контролирует сервер и код
контакт не используется для уведомлений или автоматических сообщений в telegram
«мой выбор» — локальная подборка, не бронь

## управление и проверки

временная остановка новых броней: `public.wishlist_settings.reservations_enabled=false`
отмена существующей брони по личному ключу остаётся доступна

- `scripts/wishlist-reservation-smoke.py` проверяет настоящее api на скрытом тестовом подарке и подготовленный интерфейс в трёх размерах
- `scripts/wishlist-live-release.py` проверяет опубликованную версию и сценарий двух посетителей без реальных подарков
- `.github/workflows/wishlist-smoke.yml` проверяет сайт после изменений в main
- тестовые ключи и контакты не включаются в отчёты, тестовая бронь снимается после прогона

`data.json` — публичный снимок выбранных полей notion, не автоматическая синхронизация
модели и комплектации согласуются отдельно, цены не выдумываются

## дополнительные идеи

39 подтверждённых пожеланий по-прежнему используют прежние id и тот же сервис бронирования
16 предложений вынесены отдельно в раздел «ещё идеи / сначала обсудим», не объявлены подтверждёнными и не бронируются
личные задачи и покупки собственника квартиры не опубликованы
изображения `*-full.png` используют целые предметы и исходные альфа-каналы или маски однотонного фона, без нейросетевого дорисовывания
приватные брони и портрет не изменялись
